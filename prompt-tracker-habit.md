# Промт: Веб-трекер учебных задач по разделам

## Промт для передачи агенту

---

**Роль:** Ты — опытный front-end инженер и продуктовый дизайнер. Пиши чистый, типизированный и поддерживаемый код, соблюдай единую структуру проекта и не оставляй мёртвого кода.

**Задача:** Реализуй с нуля веб-приложение «Трекер учебных задач» — локальный (offline-first) инструмент для студента. Задачи группируются по разделам-предметам; по умолчанию созданы три раздела: **Английский язык, Алгебра, Физкультура**. Пользователь добавляет и редактирует задачи, переводит их по статусам (канбан), отмечает выполнение, перемещает задачи между разделами и видит прогресс — по каждому разделу и общий.

### Технологии (строго)

- Vite + React 18 + TypeScript (strict mode)
- Стилизация: обычный CSS с CSS-переменными (без UI-библиотек и без DnD-библиотек); компоненты в `src/components`, логика — в `src/hooks` и `src/lib`
- Хранение данных: `localStorage` с версионированной схемой (`schemaVersion`) и безопасной миграцией; никакого бэкенда и внешних API
- Даты: только локальные календарные даты в формате `YYYY-MM-DD` (без `new Date().toISOString()`, чтобы не было сдвигов дня из-за часовых поясов)
- Drag & drop — нативный HTML5 DnD; для клавиатуры обязателен альтернативный способ (кнопки/меню «Переместить в…»)
- Тесты: Vitest на ключевую логику (расчёт прогресса, статусные переходы, миграция данных)

### Функциональные требования

1. **Разделы (редактируемые):** по умолчанию три — Английский язык, Алгебра, Физкультура. Пользователь может добавить свой раздел, переименовать, изменить цвет/эмодзи, переупорядочить и удалить. Удаление раздела с задачами требует подтверждения и явного выбора судьбы задач (переместить в другой раздел / удалить вместе). Архивирование раздела вместо удаления — опционально. В интерфейсе разделы — постоянный сайдбар/список с счётчиком задач.
2. **Добавление и редактирование задач:** создание в выбранном разделе, поля: название (обязательно, до 100 символов), описание (необязательно), раздел, статус по умолчанию «Запланирована», дата выполнения (необязательно), порядок. Редактирование и удаление с подтверждением; список задач сортируется, порядок меняется перетаскиванием или кнопками.
3. **Изменение статуса (канбан):** экран-доска с четырьмя колонками — **Запланирована → В работе → Отложена → Выполнена**. Перевод задачи: перетаскиванием между колонками и через меню/кнопки (для клавиатуры и мобильных). Статус можно менять вручную в любую сторону; переход фиксируется в истории задачи (минимум: когда изменён последний раз).
4. **Отметка выполнения:** быстрое действие (галочка/кнопка) на карточке задачи и на экране «Сегодня» — ставит статус «Выполнена» и дату/время отметки; повторное действие снимает отметку (возврат в предыдущий статус — «В работе», если он был). Задачи с ручным статусом «Выполнена» учитываются в прогрессе так же, но без отметки даты — датируется днём перевода.
5. **Перемещение между разделами:** drag & drop карточки в другой раздел и пункт «Переместить в раздел…» в меню задачи; операция обратима (undo-уведомление), при попытке в архивный раздел — предупреждение.
6. **Отображение прогресса:**
   - на главной — общая полоса «выполнено N из M» за сегодня и за текущую неделю;
   - по каждому разделу — полоса и процент (выполнено / активных задач), обновляются мгновенно;
   - на доске — счётчик в заголовке каждой колонки;
   - пустые состояния и подсказки, если задач или разделов нет.
7. **Статистика:** heatmap за 12 недель (интенсивность = доля выполненных задач дня, клик — список дня), текущая и лучшая серия подряд, % выполнения за 7/30 дней, столбиковый график за 30 дней (SVG/CSS без библиотек).
8. **Настройки:** тёмная/светлая тема (системная + ручной переключатель), экспорт всех данных в JSON, импорт с валидацией и откатом при ошибке, полный сброс с двойным подтверждением.

### Нефункциональные требования

- Адаптивность: 320–1440 px; на мобилке канбан переключается свайпом/табами колонок, сайдбар разделов становится верхним селектором; нижняя навигация из 4 вкладок (Сегодня / Доска / Статистика / Настройки)
- Доступность: семантический HTML, ARIA (в т.ч. для kanban-колонок и drag & drop), полная навигация с клавиатуры, контраст ≥ 4.5:1, фокус-стили
- Производительность: первая отрисовка < 1.5 с, работа без интернета после первой загрузки
- Отсутствие console-ошибок и предупреждений в проде

### Модель данных (ориентир)

```ts
type Status = 'planned' | 'in_progress' | 'postponed' | 'done'
const STATUSES: Status[] = ['planned', 'in_progress', 'postponed', 'done']

type Section = {
  id: string
  name: string
  color: string
  emoji: string
  order: number
  archived: boolean
  createdAt: string // YYYY-MM-DD
}

type Task = {
  id: string
  sectionId: string
  title: string
  description?: string
  status: Status
  dueDate?: string // YYYY-MM-DD
  completedAt?: string // ISO или YYYY-MM-DD — при отметке выполнения
  lastStatusChangeAt?: string
  order: number
  createdAt: string
  updatedAt: string
}

type Store = {
  schemaVersion: number
  sections: Section[] // по умолчанию: Английский, Алгебра, Физкультура
  tasks: Task[]
  settings: { theme: 'system' | 'light' | 'dark'; firstDayOfWeek: 0 | 1 }
}
```

### Критерии приёмки (проверь себя перед сдачей)

- [ ] При первом запуске есть ровно три раздела: Английский язык, Алгебра, Физкультура
- [ ] Можно добавить, переименовать и удалить раздел; при удалении задачи не теряются — их судьба выбирается явно
- [ ] Задача создаётся в выбранном разделе, редактируется и удаляется; данные переживают перезагрузку
- [ ] Статус переключается и перетаскиванием, и с клавиатуры/через меню; все 4 статуса достижимы
- [ ] Отметка выполнения ставит дату и учитывается в прогрессе; повторное действие снимает отметку без потери данных
- [ ] Задачу можно переместить в другой раздел (DnD и меню), операция отменяется по undo
- [ ] Прогресс по каждому разделу и общий пересчитывается мгновенно и совпадает с ручным подсчётом
- [ ] Streak и heatmap корректны при пропуске дня и при смене часового пояса/даты
- [ ] Экспорт → импорт восстанавливает состояние 1:1; битый файл отклоняется без потери данных
- [ ] Клавиатура: Tab, Enter, Space, Escape работают, фокус виден; `npm run build` и `npm test` зелёные

### Порядок работы: 10 этапов

Реализуй строго по этапам. **Перед началом каждого этапа — краткий план (3–5 пунктов), после — сдача:** что сделано, какие файлы добавлены/изменены, результат самопроверки по критериям приёмки этого этапа. Не переходи дальше, пока критерии текущего этапа не выполнены. Если этап получается большим — разбей его внутри себя на подшаги.

---

#### Этап 0 — Каркас проекта

**Цель:** пустое, но работающее приложение с настроенным инструментарием.
**Задачи:** `npm create vite` (React-TS), strict-типы, структура папок (`src/components`, `src/hooks`, `src/lib`, `src/styles`), базовый layout с 4 вкладками-заглушками и нижней навигацией, подключение Vitest, ESLint + Prettier, CSS-переменные для светлой/тёмной темы.
**Приёмка:** `npm run dev` / `build` / `test` работают; переключение вкладок рендерит заголовки и доступно с клавиатуры; README с командами есть.

#### Этап 1 — Ядро данных

**Цель:** надёжное локальное хранилище — фундамент всего приложения.
**Задачи:** типы `Section`, `Task`, `Store`, `Status` + список статусов; репозиторий поверх `localStorage` (чтение/запись/подписка), безопасный парсинг с откатом к дефолту при битых данных, миграции версий; сид-данные: три раздела по умолчанию + 5–7 учебных задач для разработки; утилиты дат (`today()`, `addDays()`, `formatDate()` — только `YYYY-MM-DD`), генератор id.
**Приёмка:** тесты зелёные; запись → перезагрузка → чтение сходится; битый JSON не роняет приложение; при пустом сторе создаются три раздела по умолчанию.

#### Этап 2 — Разделы

**Цель:** управление предметами — структура всего приложения.
**Задачи:** сайдбар/список разделов со счётчиком задач, форма добавления/переименования (валидация имени), выбор цвета и эмодзи, переключение порядка, удаление с модальным подтверждением и явным выбором судьбы задач (переместить / удалить), архивация, пустые состояния.
**Приёмка:** полный цикл create → rename → reorder → delete работает; три раздела по умолчанию видны; при удалении раздела с задачами данные не теряются молча.

#### Этап 3 — Задачи (добавление и редактирование)

**Цель:** полный CRUD задач внутри разделов.
**Задачи:** форма создания/редактирования (название 1–100 символов, описание, раздел, статус, необязательная дата выполнения), список задач активного раздела, сортировка/порядок (перетаскиванием или кнопками), удаление с подтверждением, пустое состояние раздела.
**Приёмка:** создал → отредактировал → удалил; задача сохраняется в выбранном разделе и переживает перезагрузку; без имени форму не отправить.

#### Этап 4 — Канбан: изменение статуса

**Цель:** наглядный перевод задач по статусам.
**Задачи:** доска с четырьмя колонками (Запланирована / В работе / Отложена / Выполнена) и счётчиками, drag & drop между колонками (нативный HTML5), альтернатива для клавиатуры и мобильных (меню «Переместить в…»), оптимистичное обновление с откатом при ошибке, отметка `lastStatusChangeAt`, визуальное выделение колонок-приёмников.
**Приёмка:** задача перемещается и перетаскиванием, и с клавиатуры; все 4 статуса достижимы; после перезагрузки статусы на месте; на мобилке колонки переключаются без DnD.

#### Этап 5 — Экран «Сегодня» и отметка выполнения

**Цель:** главный пользовательский цикл «увидел — отметил».
**Задачи:** список задач на сегодня (с фильтром по разделам), переключатель на прошлые дни, быстрая галочка выполнения с датой, снятие отметки с возвратом в прежний статус, строка прогресса дня «N из M», запрет отметки будущих дат, undo-уведомление.
**Приёмка:** отметка за сегодня/вчера переживает перезагрузку; повторное действие снимает отметку корректно; прогресс пересчитывается мгновенно; будущее заблокировано.

#### Этап 6 — Перемещение между разделами и прогресс

**Цель:** гибкость структуры и наглядный результат.
**Задачи:** drag & drop карточки в другой раздел + пункт «Переместить в раздел…» с undo; предупреждение при переносе в архивный раздел; полосы и проценты прогресса по каждому разделу (выполнено / активных), общий прогресс дня и недели, мгновенный пересчёт при любых изменениях.
**Приёмка:** перенос работает обоими способами и отменяется; проценты по разделам и общий совпадают с ручным подсчётом на тестовых данных.

#### Этап 7 — Статистика

**Цель:** динамика — ради неё трекер и открывают.
**Задачи:** heatmap за 12 недель (клик по дню — список задач), текущая и лучшая серия подряд, % выполнения за 7/30 дней, столбиковый график за 30 дней без библиотек, фильтр статистики по разделу.
**Приёмка:** streak корректен при пропуске дня и смене расписания; heatmap не ломается при смене часового пояса/даты; значения сходятся с ручным подсчётом.

#### Этап 8 — Настройки, экспорт/импорт, темы

**Цель:** владение данными и внешний вид.
**Задачи:** переключатель темы (системная + ручная, сохраняется), экспорт в JSON-файл, импорт с валидацией схемы и откатом при ошибке (без потери текущих данных), полный сброс с двойным подтверждением.
**Приёмка:** экспорт → импорт восстанавливает состояние 1:1; битый/чужой файл отклоняется с понятным сообщением; срос требует двойного подтверждения; тема переживает перезагрузку.

#### Этап 9 — Полировка, доступность, тесты

**Цель:** продовый уровень качества.
**Задачи:** адаптивность 320–1440 px (канбан табами на мобилке, сайдбар → селектор разделов), ARIA для kanban и DnD, полная клавиатурная навигация, видимые фокус-стили, контраст ≥ 4.5:1, пустые состояния на всех экранах, финальные Vitest-тесты (даты, прогресс, статусные переходы, перемещение, миграция, импорт), прогон линтера, чистка мёртвого кода, финальный README.
**Приёмка:** полный чек-лист «Критерии приёмки» пройден; `npm run build` и `npm test` зелёные; консоль чистая; проверено на 320 px и 1440 px.

### Ограничения

Не используй бэкенд, БД, внешние API, платные сервисы, UI/график/DnD-библиотеки. Не проси уточнений там, где решение очевидно — выбирай лучший вариант и обоснуй одной строкой.

## Как пользоваться

1. Скопируйте блок «Промт для передачи агенту» целиком — целиком или по одному этапу за раз (удобно для контроля).
2. Разделы по умолчанию и названия статусов легко поменять в блоках «Функциональные требования» и «Модель данных».
3. Для быстрого MVP можно оставить этапы 0–6, а статистику (7) и настройки (8) доделать позже.
